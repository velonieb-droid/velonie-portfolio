Case Study — GHL + Website Systems Audit

Client asked for a cleanup. The audit found an unauthorized admin, a broken booking flow, and zero attribution.

A dual GoHighLevel + website audit for a credit repair & funding consultancy, run as a systems review rather than a feature checklist — access, deliverability, revenue capture, and measurement, in that order of risk.

IndustryCredit repair & funding consultancy
EngagementGHL account audit + website audit
RoleAuditor, GHL specialist
DurationAudit phase, single engagement
Findings → Fixes

Five gaps, ranked by what they were actually costing the client

Ranked by business impact, not by module: access risk first, revenue leak second, deliverability and measurement after. Each finding maps directly to what was scoped to fix it.

Critical
Found

Unidentified Account-Admin with full access

An admin-level user with no documented ownership had standing access to the account — contacts, billing, automation, everything. No one on the client side could confirm who added them or why.

Fixed scope
Fix

Access audit + role re-provisioning

Full user/role audit, unauthorized access removed, admin roles re-provisioned with documented ownership so every account-level user is traceable going forward.

High
Found

Booking widget returning a 500 error

The public booking widget failed on load for a share of visitors — every failed load was a lead that couldn't self-book, silently, with no error surfaced to the client.

Fixed scope
Fix

Root-caused and rebuilt the embed

Traced the conflict, rebuilt the calendar embed, and verified the booking path end-to-end across entry points before signing off.

High
Found

46% of inbound calls went unanswered

Nearly half of inbound calls had no follow-up path — no missed-call text-back, no routing logic, no automated recovery. For a consultancy where inbound calls are qualified leads, this was the single largest revenue leak in the account.

Fixed scope
Fix

Missed-call text-back + routing rebuild

Automated text-back on missed calls, call routing logic reworked, and a follow-up sequence built to recover leads that would otherwise go cold.

Medium
Found

A2P 10DLC status: Rejected

SMS registration was rejected, driving a high message failure rate across every workflow that depended on text — reminders, nurture sequences, missed-call recovery, all degraded at once.

Fixed scope
Fix

Corrected registration + fallback logic

Corrected brand/campaign registration for resubmission, with fallback channel logic built into workflows for the period while approval is pending.

Medium
Found

Zero marketing attribution

No source tracking existed anywhere in the pipeline. The client couldn't tell which channel, campaign, or page produced a lead — every marketing dollar was unmeasurable.

Fixed scope
Fix

UTM + source tracking implementation

Source tracking mapped to pipeline stages, baseline reporting established so future spend can be measured against actual pipeline movement.

Method

How the audit was run

01

GHL account review

Full pass through pipelines, workflows, user roles, messaging compliance, and automation health — not a feature-by-feature checklist.

02

Website audit, cross-referenced

Ran independently, then cross-referenced against the GHL findings — the booking widget failure only became a priority once matched against the call/lead-loss data.

03

Severity-ranked reporting

Findings ordered by business risk, not by where they sit in the platform, so the client knows what breaks first if left alone.
